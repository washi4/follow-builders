Anthropic Engineering
How we contain Claude across products
Anthropic 工程团队详细拆解了如何在三大核心产品中为 AI agent 设计安全边界。随着 agent 能力增强，单纯依赖人类审批会导致 approval fatigue，因此环境层面的隔离成为关键。文章分享了三种隔离模式：claude.ai 的临时容器、Claude Code 的人类监督沙盒，以及 Claude Cowork 的本地虚拟机。团队还复盘了多个险些导致数据泄露的真实安全漏洞，例如通过合法域名进行数据外发，以及将用户作为 prompt injection 的载体。核心经验是优先在环境层设计硬边界，而非仅依赖模型层的概率性防御。
https://www.anthropic.com/engineering/how-we-contain-claude

An update on recent Claude Code quality reports
针对用户反馈 Claude Code 变笨和遗忘上下文的问题，Anthropic 公布了详细的 postmortem。问题源于三个独立的失误：为了降低延迟将默认 reasoning effort 降为 medium、一个导致长会话丢失历史 thinking 的 caching bug，以及一条为了减少废话却意外降低代码质量的 system prompt。这些改动在不同时间段影响了不同模型，导致整体体验显得不稳定。团队已回滚所有问题改动，重置了所有订阅用户的 usage limits，并承诺未来对 system prompt 的修改实施更严格的 per-model eval 和灰度发布机制。
https://www.anthropic.com/engineering/april-23-postmortem

Scaling Managed Agents: Decoupling the brain from the hands
Anthropic 推出了 Managed Agents 托管服务，其核心架构思想是将 agent 的 brain (模型与 harness) 与 hands (执行沙盒) 以及 session 日志彻底解耦。早期的单体容器设计会导致状态丢失和调试困难，解耦后不仅让容器变成了可随时替换的 cattle，还让安全边界更加清晰，确保凭证永远不会进入代码执行环境。这种设计让首 token 延迟 (TTFT) 大幅降低，并支持一个大脑动态调用多个执行环境，为未来更复杂的长周期 agent 任务奠定了底层基础。
https://www.anthropic.com/engineering/managed-agents
